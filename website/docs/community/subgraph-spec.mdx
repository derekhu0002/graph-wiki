# Architecture subgraph spec

> Authoritative source: [`community/SUBGRAPH-SPEC.md`](https://github.com/derekhu0002/graph-wiki/blob/main/community/SUBGRAPH-SPEC.md)

## What is a subgraph

A **subgraph** is a fragment trimmed from a project's full intent graph that is **independently reusable**.
It consists of `elements + relationships + views` and follows the ARCHGRAPH graph schema.

## Subgraph types

| Type | Feature | Naming domain |
|---|---|---|
| Capability | Actor + Capability | `capability` |
| Role | Actor/Role + responsibility relationships | `role` |
| Governance | Rule/Process + gates | `governance` |
| Business | business-domain elements + technology links | `business` |
| Collaboration | multiple Actors + collaboration flows | `collab` |

## Naming

```
<project>-<domain>-<type>-<seq>
  e.g. abot-overseer-capability-001
```

## Quality gate

On submission the service automatically runs ARCHGRAPH schema validation (structural completeness, valid
ArchiMate types, unique ids, relationship endpoints exist, view members exist, exactly one top-level view).
Anything that fails is rejected and not stored.

See the [full subgraph spec](https://github.com/derekhu0002/graph-wiki/blob/main/community/SUBGRAPH-SPEC.md).
