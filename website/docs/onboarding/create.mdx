# Create a project from scratch

The first step for a new project is to have its own **intent graph** (`design/KG/SystemArchitecture.json`)
and local toolchain.

## 1. Initialize the workspace (ARGO)

Use ArchGraph's ARGO toolchain to initialize the workspace — it bootstraps/validates the graph skeleton,
projection and semantic index:

- Run `argo-init` (the ARGO MCP `initializeWorkspace`): workspace bootstrap + Neo4j projection + semantic
  lifecycle (embeddings) + canonical validation.
- The ArchGraph (Graph) project's `initializeWorkspace` can be used to ensure the environment is ready.

> Constraints: Neo4j must support multiple databases (Enterprise); embeddings use Alibaba Qwen (key in ARGO's
> own `~/.argo/.env`).

## 2. Build the intent graph

A graph has three parts: **elements / relationships / views** (of ArchiMate or the chosen ontology). Use the
ARGO MCP mutation tools:

- `addArchitectureElement` / `updateArchitectureElement`
- `addArchitectureRelationship`
- `addArchitectureView` (attach views under elements; keep exactly one top-level view)

List business elements (Actor/Capability/Service) first, then add relationships and views.

## 3. Local acceptance (test-first)

Write **executable GIVEN-WHEN-THEN acceptance** for every key element, and run validation + tests:

- `validateSystemArchitecture` (schema/structure validation)
- `runArchitectureTests` (run the graph's acceptance cases)

> Rule: anything end-to-end verifiable must be verified end-to-end; formal acceptance runs in the cloud environment.

## 4. (Optional) Produce a subgraph

Trim reusable parts into a **subgraph** (the subgraph library is for community sharing, under construction):
submit with `graph_submit`.
