# Join the federation

After registering with the **federation center**, your project becomes a member that other projects in the
organization can access under authorization.

## 1. Register a member (get a projectId)

Via **Graph MCP** (remote: `https://argo.derekworkspacev5.com/mcp`):

```jsonc
// registry_register
{ "id": "<your project id>", "name": "<name>", "role": "<purpose>",
  "capabilities": ["..."], "openContent": [ /* {id,name,ref} */ ],
  "sourceRepo": "https://github.com/<owner>/<repo>", "branch": "main" }
```

- The center confirms the `id` is **globally unique** (the same id from a different source repo is rejected).
- Registration **builds your knowledge replica in the background** (clone repo → Neo4j projection + embeddings).
- Afterwards, **poll `mirror_list`** to see when the replica is ready (it is a long-running task).

## 2. Persist your identity locally

Store the returned `projectId` locally (e.g. `.argo/federation.json`: `{ projectId, sourceRepo, centerUrl, branch }`)
to use as `requester` and to tell "own repo vs external repo".

## 3. Authorize and self-read

- **Self-read**: `requester == projectId` (reading your own replica) is **implicitly allowed**.
- **Authorize others**: `registry_authorize { grantor, grantee, contentId }` (`contentId` defaults to `*` = all
  open content).

## 4. Verify

- `registry_discover` shows you and other members; `mirror_list` shows your replica `ok:true`.
- The federation page visualizes members and authorization relations: [/federation](/federation).

## 5. Framework notes (0.27+)

- **Element / relationship / view ids may be allocated by the framework** as unique semantic slugs
  (e.g. `billing-capability-002`). Treat ids as opaque — never assume the caller authored them.
- **Schema bundles** are named `schema-bundle.*` (`schema-bundle.config.json`,
  `schema-bundle.rules.json`, inline key `x-schema-bundle`, guide `GUIDE.md`); the default ontology is
  **ArchiMate 3.2**.
- **Cross-project reads** return `structuredContent` (alongside the text payload) when routed through the
  framework's optional `projectId` parameter.

> The interface and call contract are detailed in the "Graph project adaptation" spec (cross-project graph query).
