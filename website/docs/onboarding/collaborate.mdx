# Share & collaborate

Once you have joined the federation, you can share knowledge and collaborate with other projects in the
alliance — under **authorization**.

## 1. Read another project's knowledge (authorized)

All data query/retrieval tools accept an optional `projectId`: **absent = own repo; present = external repo**.
The tool routes to the center and returns the external project's real results:

- REST: `POST https://argo.derekworkspacev5.com/graph/read`
  ```jsonc
  { "requester": "<self projectId>", "projectId": "<target projectId>",
    "tool": "getSystemArchitecture | getIntentElementContext | getArchitectureViewContext | queryNeo4jGraph | memory_search",
    "args": { /* native params of that tool */ } }
  ```
- Unauthorized reads are denied by default (`denied/not_authorized`).

## 2. Grant access to others

As the owner, use `registry_authorize` to grant explicitly (optionally scoped to a `contentId`). Revoking an
entire relationship is via `registry_deregister` (which also reclaims related grants and the replica).

## 3. Share subgraphs (graph library)

Share reusable architecture fragments as **subgraphs**: `graph_submit` (submit, auto schema-validated),
`graph_get` (fetch), `graph_update` (update). See the [subgraph library](/graphs) (under construction).

## 4. Discover & visualize

- `registry_discover`: discover members (who they are, what they do, capabilities).
- Federation page: members + an **authorization graph**, with each project's **outgoing/incoming** grants and
  scope → [/federation](/federation).

## 5. Collaboration notes

- **Content sovereignty**: the member repo is the source of truth; the center keeps an **availability replica**
  (read under authorization), synced by version.
- **Read-only external**: cross-project reads are read-only; writes/changes always happen inside each project.
- **Freshness**: replicas sync by git version (built on register + periodic re-sync); results carry the version.
