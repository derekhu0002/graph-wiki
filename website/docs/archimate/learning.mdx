## Suggested learning path

### Step 1 — Build intuition for the core framework (0.5–1 day)
- Understand "three layers (Business/Application/Technology) × three aspects (structure/behavior/passive)".
- Memorize representative elements per layer (Actor/Process/Service/Component/Node/Artifact).
- Open an official example in Archi and see how layers are connected by Realization/Serving.

### Step 2 — Master relationship semantics (1–2 days)
- Focus: Composition/Aggregation, Assignment, Realization, Serving, Access.
- Practice: model a familiar scenario without overusing Association.
- Check the relationship matrix to see which relationships may connect which elements.

### Step 3 — Views and viewpoints (1 day)
- Difference between View and Viewpoint.
- Common viewpoints: Layered, Capability, Application Cooperation, Implementation & Migration.
- Practice: export 2–3 viewpoints from the same model.

### Step 4 — Practice with ArchGraph
- Read [Introduction](/docs/intro) and the [subgraph spec](/docs/community/subgraph-spec).
- Use `graph_get` to pull community subgraphs and analyze whether their elements/relationships follow the spec.
- Try trimming your own project's intent graph into a compliant subgraph and submitting it.

## Mapping to ArchGraph

| ArchiMate concept | ArchGraph usage |
|---|---|
| Business Actor | Agent / role / project overseer |
| Capability | an agent's core capability |
| Business Process | workflow / gate / acceptance process |
| Rule / Skill | governance rule / skill asset |
| Artifact | graph JSON / config files |
| View | subgraph viewpoint (at least one view) |
| Relationship matrix | types & relationships validated on graph_submit |
