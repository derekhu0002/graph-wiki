# Core concepts & elements

A quick study summary based on the ArchiMate 3.2 Specification.

## The core framework: 3 layers × 3 aspects

The ArchiMate Core Framework organizes the language into **three layers** and **three aspects**.

| | Active structure | Behavior | Passive structure |
|---|---|---|---|
| **Business** | Actor / Role | Process / Function / Service | Business Object |
| **Application** | Application Component | Application Function / Service | Data Object |
| **Technology** | Node / Device / System Software | Technology Function / Service | Artifact |

- **Layer**: Business / Application / Technology, connected by realization/serving relationships.
- **Aspect**: who does it (active structure) → what is done (behavior) → to what (passive structure).

> Additional **Motivation** (Goal / Outcome / Principle / Requirement) and **Strategy / Implementation**
> extensions express *why* and *how to deliver*.

## Element categories

### Business layer
| Category | Elements |
|---|---|
| Active structure | Business Actor, Business Role, Business Collaboration, Business Interface |
| Behavior | Business Process, Business Function, Business Interaction, Business Event, Business Service |
| Passive structure | Business Object, Contract, Representation, Product |

### Application layer
| Category | Elements |
|---|---|
| Active structure | Application Component, Application Collaboration, Application Interface |
| Behavior | Application Function, Application Process, Application Interaction, Application Service |
| Passive structure | Data Object |

### Technology layer
| Category | Elements |
|---|---|
| Active structure | Node, Device, System Software, Technology Collaboration, Technology Interface |
| Behavior | Technology Function, Technology Process, Technology Service |
| Passive structure | Artifact, Technology Object |

### Cross-layer / extensions
- **Composite**: Grouping, Location
- **Motivation**: Stakeholder, Driver, Goal, Outcome, Principle, Requirement, Constraint
- **Implementation**: Work Package, Deliverable, Plateau, Gap
- ArchGraph also uses: `Skill`, `Rule`, `Capability`, `Value Stream`, `Course of Action`

## Relationships

ArchiMate 3.2 groups relationships into four kinds (all directed), constrained by the **relationship matrix**.

| Kind | Relationship | Meaning |
|---|---|---|
| **Structural** | Composition / Aggregation | whole-part (existential / non-existential) |
| | Assignment | assign behavior/responsibility (Actor executes Process) |
| | Realization | implement (lower layer realizes upper layer) |
| **Dependency** | Serving | provide a service (Service serves the layer above) |
| | Access | access (behavior reads/writes an object) |
| **Dynamic** | Triggering / Flow | trigger / flow |
| **Other** | Association / Influence / Specialization | assoc / influence / specialization |

**Examples (correct semantics):**

```
Project Overseer (Business Actor) --(Assignment)--> Acceptance Process (Business Process)
Intent graph (Artifact)           --(Realization)--> Long-term memory (Business Object)
Scheduler (Application Service)   --(Serving)--> Business Process
Acceptance Process (Business Process) --(Access)--> Test Report (Business Object)
```

> **Common pitfall**: making everything an *Association*. Prefer Assignment (executes), Realization
> (implements), Serving (serves), Access (accesses) — so the graph carries meaningful, inferable structure.

## Views and viewpoints

- **View**: a representation of the system from one concern — a subset of elements plus relationships.
- **Viewpoint**: a convention for a class of views (Layered / Capability / Cooperation / Implementation…).
- In ArchGraph, a subgraph has at least one top-level view; sub-views attach under a parent element.
- A graph has at most one top-level (parentless) view.
