# ArchiMate 核心概念与元素

基于 ArchiMate 3.2 Specification 整理的学习速览。

## 核心框架：三层 × 三面

| | 主动结构 | 行为 | 被动结构 |
|---|---|---|---|
| **业务层 Business** | Actor / Role | Process / Function / Service | Business Object |
| **应用层 Application** | Application Component | Application Function / Service | Data Object |
| **技术层 Technology** | Node / Device / System Software | Technology Function / Service | Artifact |

- **层**：业务 / 应用 / 技术，由"实现/服务"关系贯穿。
- **面**：谁做（主动结构）→ 做什么（行为）→ 对什么做（被动结构）。

> 另有 **Motivation**（Goal / Outcome / Principle / Requirement）与 **Strategy / Implementation** 扩展，表达"为什么"与"怎么落地"。

## 关系分类

| 类别 | 关系 | 语义 |
|---|---|---|
| 结构 | Composition / Aggregation | 整体-部分 |
| | Assignment | 指派（Actor 执行 Process） |
| | Realization | 实现（下层实现上层） |
| 依赖 | Serving | 服务提供 |
| | Access | 访问（读/写对象） |
| 动态 | Triggering / Flow | 触发 / 流转 |
| 其他 | Association / Influence / Specialization | 关联 / 影响 / 特化 |

> **常见误区**：一切关系都用 Association。应尽量用 Assignment（执行）、Realization（实现）、Serving（服务）、Access（访问）表达真实语义。

## 视图与视角

- **View**：从某一关注点看系统的一种表示（元素子集 + 关系）。
- **Viewpoint**：某类视图的约定（Layered / Capability / Cooperation / Implementation…）。
- ArchGraph 中每个子图至少含 1 个视图；子视图可挂到父元素之下；顶层视图最多 1 个。
