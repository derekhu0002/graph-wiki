# 架构

ArchGraph 有两个使其灵活、可演进的架构属性。它们共同支撑主页上的[价值流](/)：为项目构建图谱，以及把众多项目组合成组织级图谱。

## 1. 本体可插拔

一张图由它的**本体**定义——即元素与关系的类型体系和规则。本体**可替换、可自定义**：每个项目都能定义并演进自己的图谱。

这正是**开闭原则**：可扩展、可替换，而无需重写框架。

- ArchiMate 3.2 是**默认**本体——被广泛采用、有正式规范与关系矩阵的企业架构标准。见[本体货架](/ontologies)。
- 其它本体（安全、数据、流程…）可陆续加入；货架是目录，不是硬限制。

## 2. 读写与图谱解耦

**读写 MCP** 与任何具体图谱/本体解耦。它负责与本体无关、但对图谱的生产与消费**极其关键**的能力：

| 能力 | 覆盖 |
|---|---|
| **写入治理** | 去重 / 无损 / 墓碑门禁——知识不会被悄悄丢失。 |
| **读写性能与效率** | 通过子图限定实现 Token 精益读取；写入路径随图增大仍保持低成本。 |
| **检索准确率与召回率** | 向量 + 图谱混合检索、rerank、阈值、两步回忆。 |
| **度量** | 剖面评测框架（场景 × 规模 × 指标）——见[指标与评测](/docs/metrics)。 |

因为这些能力在 MCP 里（而非本体里），**你可以独立、持续地改进它们**——更好的治理、更快的读取、更高的召回——而无需改动任何项目的图谱或本体。

## 为什么重要

- **不锁定**：每个项目可替换/扩展本体；可随时间引入新本体。
- **可演进**：读写管线沿可度量指标持续优化。
- **可组合**：同一套框架既能构建单个项目图，也能把众多项目组合成组织级图谱（[联邦](/federation)）。

> 我们优化的指标体系、如何度量、当前结果与对照评测，见[指标与评测](/docs/metrics)。
