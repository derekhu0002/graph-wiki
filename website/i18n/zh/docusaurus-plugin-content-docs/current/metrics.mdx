# 指标与评测

本页四部分：指标体系及每个指标解决的问题、我们如何度量与优化、当前结果、以及我们如何与基线做对比。（内部基线；重在方法。）

## 1. 指标体系

我们把**检索/记忆质量**与 **Agent 成本**分开，并始终把质量指标与成本指标配对，避免悄悄用速度换召回。

| 指标 | 解决什么 |
|---|---|
| 成功率 / 准确率 | 任务是否得到正确答案。 |
| 证据召回率 | 是否取全了必需证据（不漏）。 |
| 证据精度 | 取回的证据是否相关（不噪）。 |
| 首次命中 | 首条命中是否就正确（减少往返）。 |
| 轮次 / 工具调用（分后端）/ 后端往返次数 | Agent 的代价；图↔仓往返是真正的成本放大器。 |
| Token（in/out/reasoning）与压缩率 | 上下文成本。 |
| 时延（模型 / MCP / 仓） | 响应性。 |
| 拒答正确率 / 幻觉率 | 无答案时能否正确拒答。 |
| 写入治理（去重 / 无损 / 墓碑） | 写入时知识不被悄悄丢失。 |

底层仍用标准 IR 指标：**Precision / Recall / MRR / Hit Rate@K**。

## 2. 如何度量与优化

- **剖面评测框架**：沿 **场景 × 规模 × 指标** 三条轴评分，而不是一个总分。场景含精确/结构定位、语义定位、多跳导航、图仓合成、时间/版本/冲突、拒答、写入/登记、仓内内容定位。
- **可执行 harness**：题集 + runner（如记忆评测 runner 与 Agent 成本—召回 harness），结果可复现、可回归。
- **召回优先红线**：任何以缩小候选池换来的提速，都必须由显式失败清单暴露，不得掩盖。

## 3. 当前方案与结果

机制：三层记忆（T1/T2/T3）、两步回忆（先按语义定位 → 再取全文）、混合检索配 rerank 与召回阈值、子图限定精益读取。

有代表性的内部基线（来自我们的 harness；小样本、单项目——见注意事项）：

- 记忆评测：约 28/28 成功，不可答时正确拒答；时延低（毫秒级）；上下文压缩率约 94.5%。
- Agent 成本—召回：导航任务上证据召回完整，轮次少、Token 预算小。

> 这些是小样本内部数字，不是跨分布基准。

## 4. 对照评测

- **E1 —— 机制对照（开/关 MCP）**：同仓、同模型、同提示；唯一变量=是否挂图谱 MCP。（注意：仓本身已按框架规则塑形，E1 会系统性**低估**框架价值。）
- **E2 —— 制度对照**：用框架建的仓 vs 未用框架建的仓，各用其原生检索；同一素材/Agent/任务集。衡量框架的总价值。
- **E2′ —— 消融**：从框架仓剥离 curation（图 JSON / 摘要 / commit 账本），在内容更接近的前提下比 ON vs OFF。
- **基线对比（如 LightRAG）**：同一 Agent、同模型、同工作流；双 MCP 后端（ArchGraph vs LightRAG）严格隔离 + 中性指令，**唯一变量=记忆后端**。
